## Prioritized fix list

### Blockers

1. **B1 — Webhook idempotency drops the event on every transient failure.** `src/lib/payments/webhook-service.ts:61-86`. `applyStripeEvent` claims the `StripeWebhookEvent` row (unique on `eventId`) before routing; a throw in `route` returns 500, Stripe retries with the same `event.id`, `claimEvent` returns `false`, the retry is classified `'replay'` and silently dropped. Customer is charged at Stripe, order stays `PLACED`+`UNPAID`, stock stays reserved, no alert. Delete the claim row on throw, mark it `failed` so retries re-run `route`, or claim after success.

### Majors

2. **M1 — `handBackUnsafeCharge` refund-then-transition is not atomic.** `src/lib/payments/webhook-service.ts:190-235` (also `:234` per rules review). The Stripe refund runs outside any transaction; the `PaymentRefund` insert commits, then `transitionOrder('CANCELLED')` runs separately. If the transition loses a race or hits the illegal-transition guard, the customer is refunded in full but the order stays `PLACED` with reserved stock and the `auto_refunded` audit row already claims success. Order the work so state change and refund cannot diverge, or compensate on transition failure.
3. **M2 — `postOfflinePayment` accepts cash/check against CANCELLED or COMPLETED orders.** `src/lib/payments/offline-payments.ts:52-88`. The guard only refuses `DRAFT`/`DISCARDED`; every other status is accepted. Posting cash against a cancelled order re-flips `paymentStatus` to `PARTIALLY_PAID`/`PAID` with no stock behind it. Restrict the gate to `PLACED` and `IN_FULFILLMENT` (or also check `paymentStatus !== 'PAID'`).
4. **M3 — `postOfflinePayment` has no upper bound against the outstanding balance.** `src/lib/payments/offline-payments.ts:42-87`. Only `MAX_PAYMENT_CENTS = 5_000_000` and `positive` bind it. A staff member can post $5,000 cash against a $50 order; `recomputeOrderPaymentStatus` marks it `OVERPAID` and nothing reconciles. Asymmetric with the refund path, which caps at `refundable`. Cap `amountCents` at `order.totalCents - order.amountPaidCents` or document overpayment as a decision.
5. **M4 — Line-total formula duplicated across four call sites.** `src/lib/checkout/checkout-summary.ts:243`, `src/lib/orders/order-service.ts:373`, `src/lib/orders/customer-orders.ts:126`, `:144`. All compute `line.lineTotalCents + sumCents(line.addOns.map(a => a.lineTotalCents))`. Extract `lineTotalWithAddOns(line)` into `lib/orders`.
6. **M5 — Fulfillment-method fetch + `FeeSubject` build duplicated.** `src/lib/checkout/checkout-summary.ts:148`, `src/lib/orders/order-service.ts:366`. Same `findMany` select, same `Map<id, method>`, same subject assembly; only the `key` differs. Also the "method missing" throw is duplicated (`methodOf` vs inline). Extract `feeSubjectsFrom(packages, keyOf)`.
7. **M6 — `INVALID_GREETING` returned for delivery-day and recipient errors.** `src/lib/checkout/greetings.ts:94`, `:98`. Codes are greeting-scoped but the function handles delivery days too; a caller switching on `code` cannot tell whether the greeting or the day was wrong. Rename to a neutral code or split delivery-day codes from greeting codes.
8. **M7 — Destination-field list and adapter built twice with divergent defaults.** `src/lib/checkout/greetings.ts:148` (`LineDestination` + `asDestination`), `src/lib/orders/grouping.ts:26`, `:146` (`PACKAGE_DESTINATION_FIELDS` + `pickPackageDestination`). `asDestination` substitutes `''` for missing `recipientName`/`fulfillmentMethodId`; `pickPackageDestination` substitutes `null`. The `''` path is defensive for a case `linesForRecipient` already filters out, so the drift is silent. Unify into one `toPackageDestination(line)`.

### Minors

9. **m1 — Staff can cancel a PAID order without a refund.** `src/app/(admin)/admin/orders/actions.ts:88-101`, `src/lib/orders/state-machine.ts:14-21`. State machine allows `PLACED→CANCELLED` and `IN_FULFILLMENT→CANCELLED` with no payment-status check; `transitionOrder` releases stock but does not touch payments. Gate cancel-on-paid behind an explicit "refund first" step or surface the outstanding paid amount on the cancel confirmation.
10. **m2 — In-memory rate limiter is per-process and decorative on serverless.** `src/lib/http/public-guards.ts:19-47`. The `Map` is empty on every cold start, so the webhook's 240/min and client-error's 60/min limits do not bind in production on Vercel. Acknowledged in code; shared store (Upstash/edge config) is a P12 concern.
11. **m3 — `refundThroughGateway` idempotency key collides on two same-amount refunds of one payment.** `src/lib/payments/offline-payments.ts:200-215`. Key is `staff-refund-${payment.id}-${amountCents}`; a second same-amount refund reuses Stripe's first receipt, then `PaymentRefund.create` collides on the unique `reference` index and throws a raw `P2002`. Money is not doubled but the staff member sees an unhandled Prisma error and the second reason is lost. Make the key unique per call or detect the duplicate and return a user-facing message.
12. **m4 — `attachGuestCustomer` lets a guest attach an order to any email they can type.** `src/lib/checkout/checkout-service.ts:162-198`. A guest typing a victim's email links the order to that customer row; the victim sees it on sign-in. Documented as decision 8 (accepted design); flagged only because the security review asked. If unwanted, require email verification before linking.
13. **m5 — `postStripePayment` catches P2002 on a `Payment.reference` unique index that does not exist.** `src/lib/payments/webhook-service.ts:178-181`, `prisma/schema/orders.prisma:182`. `Payment.reference` is `String?` with no `@unique`; the catch is dead code and the comment mis-describes the schema. The real guard is `claimEvent` on `StripeWebhookEvent.eventId`. Remove the dead catch or add the missing unique index.
14. **m6 — Price conflicts are not re-checked inside `finalizeOrder`.** `src/lib/orders/order-service.ts:39-113`. `findCheckoutConflicts` runs at render time and blocks `payAction`; `finalizeOrder` only checks season-open, non-empty, fully-assigned. The `expectedTotalCents` guard in `startCheckout` compares two snapshot-derived values, so it cannot detect a catalog price move in the render→pay window. Stock IS re-checked at finalize via `reserveInventoryFor`. EXPECTED 3 is satisfied by the render-time check; this is a defense-in-depth gap.
15. **m7 — Offline (cash/check) refunds have no idempotency guard.** `src/lib/payments/offline-payments.ts:137-198`. `refundable` is read outside the transaction; two concurrent staff refunds on the same payment could both pass `amountCents > refundable` and both insert before the order lock serializes them — over-refunding a cash/check payment. Stripe refunds are protected by the gateway idempotency key; offline refunds have none. Low-impact (requires concurrent staff) but the ledger would be wrong.
16. **m8 — `localPaymentIntentId()` is exported and unused.** `src/lib/payments/local-gateway.ts:53-55`. `payLocalHostedSession` derives the intent id inline. Dead code; remove.
17. **m9 — `payAction` parses the tamper-guard total without a guard.** `src/app/(storefront)/order/checkout/actions.ts:80`. `Number(trimmedField(...))` yields `NaN` on a malformed field; `startCheckout`'s `!==` check refuses `NaN` incidentally. Replace with `z.number().int()` to make the intent observable.
18. **m10 — `rememberGreetings` writes per-row in a loop.** `src/lib/checkout/greetings.ts:136-141`. N recipients → N `updateMany` round trips. No correctness issue; will not scale to the 1k-order/5k-package crunch target (G-024).
19. **m11 — `isAssigned` / `isAssignedLine` type-guard duplicated.** `src/lib/checkout/checkout-summary.ts:259`, `src/lib/orders/order-service.ts:189`. Byte-identical predicate; each narrows to its own local type. Extract a shared `isLineAssigned(line)` guard.
20. **m12 — `findOwnedDraftOrder` reimplements `findOwnedDraft` with a different key.** `src/lib/checkout/greetings.ts:144` vs `draft-access.ts:109`. Same shape, different key field. Unify into `findOwnedDraftBy(owner, key)` or re-export.
21. **m13 — `mergeInventoryDemand` and `stockConflicts` build the same demand map.** `src/lib/orders/order-service.ts:227`, `src/lib/checkout/validation.ts:122`. Same key scheme (`product:${id}` / `addon:${id}`), same filter on `tracksInventory`, same accumulation. Extract `inventoryDemand(lines)`.
22. **m14 — `LOCAL_PAY_UNAVAILABLE` conflates two failure modes.** `src/lib/payments/local-hosted.ts:67`, `:101`. Same code for a configuration error (provider not local) and a transient POST failure. Messages differ; code does not.
23. **m15 — `CHECKOUT_NOT_READY` conflates "no draft" and "blocked".** `src/lib/checkout/checkout-service.ts:54`, `:57`. Same code for "your order was not found on this browser" and "your order has unassigned items / conflicts / no delivery day." Messages differ; code does not.
24. **m16 — Redirect-with-query-param helper forked three ways.** `src/app/(storefront)/order/checkout/actions.ts:100`, `src/app/(storefront)/order/confirmation/actions.ts:26`, `src/app/(admin)/admin/orders/actions.ts:103`. Three patterns for "redirect to a path with one or two query params." `builderHref` is the shared helper; the other two build URLs by hand. Soft (shapes differ) but repeated.
25. **m17 — `order-service.ts` is 414 lines with mixed concerns.** `src/lib/orders/order-service.ts`. Holds state transitions, inventory reservation, package creation, fee charging, and settings reading. Under the 500-line threshold but P4 flagged it as "worth watching" and P5 grew `chargeFulfillment` and added `readRateRules`. The inventory half could live in `lib/orders/inventory.ts`.
26. **m18 — `transitionOrder` does not re-check staff permission; money services do.** `src/lib/orders/order-service.ts:124`, `src/lib/payments/offline-payments.ts:217`. Money services re-check `orders.manage` (documented as "the service decides who may move money"); `transitionOrder` trusts the route's `requirePermission`. A future POS screen calling `transitionOrder` directly would inherit no permission gate. Pattern is inconsistent.
27. **m19 — `freePhone` returns an opaque partial spread under a boolean-sounding name.** `src/lib/checkout/checkout-service.ts:200`. Returns `{}` or `{ phone, normalizedPhone }` spread into `db.customer.create`. Name reads as "is this phone free?" (boolean) but it returns a partial of the customer create input. Rename to `claimablePhoneFields` or `phoneFieldsIfFree`.
