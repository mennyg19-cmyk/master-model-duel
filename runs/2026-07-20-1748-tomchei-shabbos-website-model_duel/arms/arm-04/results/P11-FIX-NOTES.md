## Fixed — majors (8/8)

| # | Finding | What changed |
|---|---|---|
| F1 | A campaign was marooned in `SENDING` if the recipient loop threw | The loop in `sendCampaign` (`src/lib/email/campaigns.ts`) is wrapped, and a throw puts the campaign back to `DRAFT` before rethrowing. Per-recipient idempotency already meant a rerun writes nothing new, so the recovery is simply "press it again" — the letters already queued stay queued and the rest go out. Proved over HTTP by smoke S2g. |
| F2 | Claim expiry was shorter than the worst-case batch, and the terminal writes had no status guard | `CLAIM_EXPIRY_MS` is now derived rather than guessed: `DEFAULT_SWEEP_LIMIT × PROVIDER_REQUEST_TIMEOUT_MS` plus a margin, so it cannot silently fall behind a change to either. Both terminal writes go through one `recordTerminal`, which updates `where: { status: 'QUEUED' }` — a late second sweep can no longer overwrite `providerReference` or add a second attempt row to a message that already landed. |
| E | `rejectWith` duplicated across four action files, in two shapes and two flash keys | One `rejectWith(basePath, message)` in `src/lib/forms/flash-redirect.ts`, next to the `redirectWithFlash` it wraps. All four call sites use it, and they all use `?problem=` — the one key `FlashMessages` reads. |
| D | `isUniqueViolation` duplicated verbatim in three modules | New `src/lib/core/prisma.ts` holds `isUniqueViolation` (P2002) and `isMissingRecord` (P2025) over one `hasPrismaCode`. `outbox.ts`, `campaigns.ts` and `catalog/admin.ts` import it; `db-client.ts` stays a type-only module. |
| F | `settings/actions.ts` was a mixed-concern god file that P11 deepened | The three email actions and their schemas moved to `src/app/(admin)/admin/settings/email/actions.ts`, beside the page that posts to them. What was genuinely shared went to `src/lib/admin/settings-form.ts` (`wholeNumber`, `firstMessage`, `auditSettingChange`) rather than being copied — that helper also removed the `audit()` wrapper repeated through the remaining file. |
| G | `CampaignSendSummary` was a redundant alias for `OutboxResult` with a parallel counting system | Retired. `queueOneRecipient` returns an `OutboxResult`, and `sendCampaign` folds them with the `addResults` that `outbox.ts` already exported. The string-key round trip is gone. |
| H | `SENDING` was written but never displayed; the hub rendered it as Draft | New `CampaignStatusBadge` (`admin/email/campaign-status.tsx`) maps all three states to a label and tone from one table. Both the hub and the campaign page use it, and the campaign page's wording follows the state, so a campaign mid-send no longer looks editable and unsent. |
| C | Missing `.scratch/PHASE-P11-STATUS.md` and `.scratch/PHASE-P11-SMOKE.md` | Both exist and were regenerated by this pass from a real run. See Verification — every phase's evidence file was regenerated, not just P11's. |
