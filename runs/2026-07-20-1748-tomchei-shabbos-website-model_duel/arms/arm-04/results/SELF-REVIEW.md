| F-01 | blocker | `src/lib/payments/webhook-service.ts:136` (`completeCheckout`) | A correct card payment is automatically refunded if the order has already moved to `IN_FULFILLMENT`. The safety check is `order.status !== 'PLACED' \|\| chargedCents !== order.totalCents`, and `IN_FULFILLMENT` is a normal state for an unpaid order — `src/lib/payments/offline-payments.ts:69` explicitly allows posting payment against it, and staff can bulk-move `PLACED → IN_FULFILLMENT` with no payment requirement (`src/lib/orders/bulk-actions.ts:32`). On a delayed or retried webhook the customer's money is handed back, a refund notice is emailed, and the order stays in the packing queue reading UNPAID. Because `orderIsPlaced` is false the order is not even cancelled, so stock stays held against an order nobody paid for. | Make the unsafe test about the amount, not the stage: accept `PLACED` and `IN_FULFILLMENT` as payable (reuse the same status list `offline-payments.ts` uses so the two cannot drift), and keep the auto-refund for `CANCELLED`/`COMPLETED`/`DISCARDED` and for an amount that does not match `totalCents`. |

## What the pass did not find

Worth recording so the absence is not read as a gap in the review:

- `npm run typecheck` and `npm run lint` both pass with no output.
- No `TODO`, `FIXME`, `@ts-ignore`, `@ts-expect-error`, `eslint-disable` or `as any` anywhere in `src/`.
